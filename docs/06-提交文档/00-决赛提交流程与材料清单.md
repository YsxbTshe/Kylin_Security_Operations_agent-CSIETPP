## 一、决赛提交要求

决赛作品 = 初赛全部内容（源码、可执行文件、PPT、开发文档、演示视频）**+ 1 分钟以内作品亮点短视频**。

开发文档将统一组织专家评审，`01`–`05` 五份 `.docx` 应在脱离源码的情况下保持内容完整、术语一致、结论可验证。所有提交件均以本次构建产物和现行架构为准。

## 三、源码包的裁剪口径

`07` 不是仓库全量快照，按三类剔除。剔除项在包内保留说明文件，便于核对裁剪范围。

| 剔除内容 | 理由 |
|---|---|
| `rag-corpus/**/*.pdf`（麒麟官方手册 5.7MB） | `COPYRIGHT.md` 承诺第三方材料**不随交付物分发**。不剔除即与自己的版权声明矛盾。`.md` 结构化摘录保留，RAG 导入流程仍可复现 |
| `docs/ppt/*.png`（官方赛题解析截图 15MB） | 同上，第三方版权 |
| `docs/*.bak.pptx` | 生成脚本的输入基线，非交付物 |
| `docs/{01-架构设计,02-部署运行,03-项目状态,04-后续计划,05-评估方案,07-学术论文,08-决赛冲刺,99-归档,组会同步}` | 内部设计、评估与项目管理材料；正式提交文档统一位于 `docs/06-提交文档` |

裁剪后源码包 **28MB → 3.2MB**，`docs/` 占比从 82% 降到合理区间。

## 四、执行流程

```bash
# 1. 核对工作区变更范围、确认全部测试通过
git status --porcelain
cd services/backend && mvn -B verify && cd -
(cd agents/node-executor  && go build ./... && go vet ./... && go test ./...)
(cd agents/workspace-runner && go build ./... && go test ./...)

# 2. 文档口径门禁（两条都必须绿）
python3 scripts/verify-doc-consistency.py
bash scripts/export-submission-docx.sh --check

# 3. 构建提交包（含 11 项自检，任一红灯即中止）
bash scripts/build-submission.sh

# 4. 用户补入完整演示视频后重新自检；亮点短视频已由构建脚本复制
cp <演示视频> build/submission/08-演示视频.mp4
bash scripts/build-submission.sh --check      # 会校验短视频时长 ≤60s

# 5. 留档：提交前记录哈希，便于事后自证提交内容
cat build/submission/MANIFEST.sha256
```

## 五、打包自检项（脚本自动执行）

1. 必交件齐全（开发文档 5 + 安装包 + 源码 + PPT）
2. 演示视频存在
3. 亮点短视频存在**且 ≤60 秒**（用 ffprobe 实测时长）
4. 安装包不含第三方依赖目录、构建缓存或 sudoers 配置，节点 Agent 采用受限账户与独立 privhelper 的特权分离机制
5. 任何包内无密钥本体（`TEST_ONLY` 测试向量除外，它是源码的一部分）
6. 安装包 `secrets/` 下无 PEM
7. 源码包无 `node_modules` / `dist` / `target` / `vms` / `.secrets` / `.env`
8. 源码包含 `LICENSE`
9. 第三方受版权材料未随包分发（兑现 `COPYRIGHT.md`）
10. 三架构可执行文件齐全（node-executor + privhelper × amd64/arm64/loong64）
11. 签名清单工具数 = 46（32 只读 / 14 写 / 10 强制审批），且开发文档中的工具、权限和执行链路口径一致

## 六、两个视频的录制要点

**完整演示视频**由用户后续补入，本轮不处理。录制应基于现行架构，建议动线：

1. 登录 → 新建任务，自然语言下达（如"检查磁盘占用并清理过期日志"）
2. 计划产出 → 风险分级 R3 → **转人工审批**（用第二账号 secops 审批，体现职责分离）
3. 审批通过 → 节点执行 → 结果回传
4. 打开「安全试判」页展示 SM2-with-SM3 审批令牌的字段级绑定与一次性消费（签名覆盖 `ApprovalClaim` 全部 17 个字段，端侧对其中 13 个身份字段逐字段复判）
5. 任务详情 → 哈希链一键验链通过
6. 补一个反面样例：AUTO 模式下写工具因 `riskFloor R3 > 自动批准上限 R2` 被拒

**亮点短视频（≤60s）**采用单一安全主线：自然语言意图进入 R3 风险判定、ABAC 授权和人工审批流程；privhelper 独立验签并执行固定操作；最终展示哈希链校验结果与 46 个签名工具清单。

## 七、提交前补充材料

1. 用户补入完整演示视频 `08-演示视频.mp4`；该视频不在本轮文档处理范围内。
2. 将银河麒麟 V11 aarch64 真机实测记录、运行日志及必要截图归入验收证据集。
3. 执行 `bash scripts/build-submission.sh --check`，确认全部提交件、哈希清单和视频规格通过校验。
